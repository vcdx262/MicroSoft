# Constraints — Data Protection

Hard limits the design must work within. If a constraint changes, revisit the affected controls/decisions.

| ID | Constraint | Implication |
|---|---|---|
| **C-1** | **Pentest work needs broad outbound internet** (download tools, hit targets, research). | A blanket deny-by-default egress allowlist may be impractical. Favors a tight *session boundary* + identity/content controls + *monitoring* over hard egress blocking. The full allowlist is appropriate only for non-pentest analyst desktops. |
| **C-2** | **Entra-only identity, no Active Directory.** | No domain Group Policy. Host controls land via Intune (rev1), CSE/registry, or local policy. |
| **C-3** | **Overlapping per-customer vNets, never peered** (ADR 0002). | Egress firewalling can't be centralized in a shared hub — Azure Firewall would be **per vNet** (per-customer cost). |
| **C-4** | **rev0 scope** excludes Intune, Conditional Access/MFA, and CMK. | Several controls (CA app-enforced restrictions, Intune-pushed policy) are **rev1** until that scope opens. |
| **C-5** | **Licensing gates the controls — CORRECTED 2026-06-21.** The tenant SKU `O365_BUSINESS_PREMIUM` is **Microsoft 365 Business _Standard_**, NOT Business Premium (classic naming trap; real Business Premium = SKU `SPB`). Confirmed via service plans: **no `AAD_PREMIUM` (Entra P1), no Defender for Business, no Purview DLP/AIP**. So on the current base: **no Conditional Access, no Tenant Restrictions, no Defender, no advanced DLP** — only **Security Defaults** (tenant-wide) or legacy per-user MFA for 2FA. To test the planned controls, acquire **Entra ID P1** (CA + TRv2, ~$6/user) or **real Microsoft 365 Business Premium** `SPB` (P1 + Defender for Business + cloud DLP + labels + Intune, ~$22/user); **Endpoint DLP / enterprise** still need **E5**. Plan (2026-06-21): assign **Business Premium** to `lab1` (swap off the Standard seat). | Earlier "lab1 on Business Premium covers most controls" was WRONG — it was Business Standard. Real testing needs a P1/Business-Premium/E5 purchase. |
| **C-6** | **AVD clipboard supports directional + data-type control** (corrected 2026-06-18): host-pool RDP property is on/off, but the session-host "clipboard transfer direction and data types" setting (Intune/GPO) allows one-way (e.g., paste-in, block copy-out) and text-only restrictions. Client support varies (Windows/macOS/iOS/web yes; Android/Quest no). Host-pool default is now **off**; our config explicitly set it **on**. | Clipboard isn't all-or-nothing — we can allow paste-in while blocking copy-out via session-host policy. |
| **C-7** | **Personal (persistent) host pool** (ADR 0005). | Re-imaging existing hosts is destructive; day-2 control changes to live hosts come via Intune/scripts, not image swaps. |
| **C-8** | **Consultants are local admins** on their session host (Virtual Machine Administrator Login granted). | A determined malicious admin can undo host-level controls. Host controls raise the bar / stop accidental & casual exfil; they are not a hard barrier against a trusted admin turned adversary — see [A-1](assumptions.md). |
| **C-9** | Current egress is **NAT Gateway + NSG allowing broad outbound 80/443** to Internet. | This is permissive relative to R-1; tightening/monitoring it is a key open item. |
